# 兼容模式（启动看门狗）

## 它解决什么问题

桌宠的窗口是 **全屏 + 透明 + 置顶 + 逐像素鼠标穿透**，这类窗口在 Windows 上走 DWM 的分层合成路径。
第三方输入法会往 GUI 进程注入 DLL 并 hook 窗口与输入相关 API，搜狗 16.x 会带进来这些：

| 组件 | 作用 |
|---|---|
| `Components/IChat/*/ichat_bundle64.dll` | 聊天增强 |
| `Components/isgpet/*/isgpet_bundle64.dll` | 搜狗桌面宠物 |
| `Components/PicFace/*/PicFace64.dll` | 表情 |
| `Components/systembeautify/*/systembeautify_bundle64.dll` | 系统美化（hook DWM 相关 API） |
| `System32/SogouPY.ime`、`SogouTSF.ime` | 输入法本体（TSF/IMM） |

一旦这些 hook 和 Chromium 的初始化顺序撞上，Chromium 会在原生层 `CHECK()` 失败并直接
`__debugbreak`，异常码 **`0x80000003`（STATUS_BREAKPOINT）**。表现是：双击后系统卡几秒 →
窗口一直没出现 → 进程消失。**这种崩溃 JS 层接不住**——`uncaughtException`、
`render-process-gone`、`crashReporter` 都不会触发，进程被系统直接回收。

所以项目侧能做的只有两件事：**预防**（能判定环境时用更保守的参数）和**兜底**（崩过一次之后，
下次启动自动换参数）。`app/boot-guard.js` 就是后者。

## 怎么工作

每次启动往 `%APPDATA%\桌宠\boot-guard.json` 写阶段：

```
process-boot  →  window-created  →  page-loaded  →  ready
```

- `ready` 是终态。正常退出不会覆盖它，所以**不会被误判成崩溃**。
- 下次启动时，如果文件里停在 `process-boot` / `window-created` / `page-loaded`，且距上次启动
  在 10 分钟内（排除关机、任务管理器强杀这类情况），判定为"启动期崩溃"，兼容等级 +1。
- 每次判定都往 `%APPDATA%\桌宠\boot-guard.log` 追加一行，包含：等级、上次停在哪个阶段、
  检测到的输入法安装路径、Electron 版本、系统版本、各阶段耗时。

## 等级

| 等级 | 做了什么 | 代价 |
|---|---|---|
| L0 | 正常 | — |
| L1 | `disable-features=TSFImeSupport`（不启用 Windows TSF 输入支持） | 桌宠内输入框可能用不了只走 TSF 的中文输入法 |
| L2 | L1 + `app.disableHardwareAcceleration()` + `disable-gpu-compositing` | 透明窗口改走软件合成，CPU 占用升高、动画可能掉帧 |
| L3 | L2 + 延迟 1.2 秒建窗 + 置顶级别从 `screen-saver` 降到 `normal` | 启动慢约 1.2 秒 |

## 用户怎么用

- **什么都不用做**：崩过一次之后，下次双击会自动按更高等级起来，托盘点顶部会出现
  「🛡 兼容模式 Lx — 点这里恢复默认」。
- 点了那条就清零（下次启动按正常模式），如果又崩，看门狗会重新降级。
- 命令行：
  - `桌宠.exe --compat=2` 本次强制 L2（不写文件）
  - `桌宠.exe --compat-off` 本次按 L0 跑（排查用）
  - `桌宠.exe --compat-reset` 清零并清失败计数

## 反馈问题时抓什么

1. `%APPDATA%\桌宠\boot-guard.log`（一行一次启动，含崩溃判定与阶段耗时）
2. `%APPDATA%\桌宠\boot-guard.json`（当前等级）
3. 如果进程留下了 dump（`%LOCALAPPDATA%\CrashDumps\桌宠.exe.*.dmp`），一并给

日志里 `BOOT level=N prevPhase=xxx` 这行直接说明上次死在哪一步：
- `prevPhase=process-boot` → 崩在 Electron 起来之前（注入/加载期）
- `prevPhase=window-created` → 崩在窗口创建或合成初始化
- `prevPhase=page-loaded` → 崩在页面加载完之后

## 为什么不用别的办法

- `app.on('render-process-gone')` / `crashReporter`：只管渲染进程，主进程原生崩溃看不到。
- 在 JS 里 try/catch：原生 `CHECK` 不走 JS 异常。
- 默认就关 TSF / 关硬件加速：会牺牲所有正常用户的输入法与性能，代价太大，所以只在"崩过一次"后启用。
