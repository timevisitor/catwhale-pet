# 桌面走动 / 自由巡游（v0.7.0）

桌宠可以在屏幕的一块**自己框选的范围**里溜达，也可以听聊天里的明确指令走一段。
本文件只写这一版新增的东西：范围、巡游、聊天指令、边界与优先级，以及怎么验。

## 一句话玩法

设置 → 🚶 桌面走动 → 点「框选走动范围」，在屏幕上拖一个矩形（**Esc 取消**）→ 需要它自己溜达就勾「自由巡游」。
也可以在聊天里直接说 **「向左走」「往右走 200 像素」「停下」**。

## 文件与职责

| 文件 | 负责 |
|---|---|
| `web/walk-geom.js` | 纯几何：拖拽矩形、与工作区求交、**角色画布包围盒**、推进、朝向、按比例换算范围、随机目标（无 DOM，Node 可直接 require） |
| `web/walk-command.js` | 纯解析：把「向左走 / 往右走 200 像素 / 停下」解析成意图，并生成中文反馈（宁可漏判，不误判） |
| `app/walk-config.js` | 纯 Node 配置：`<userData>/walk.json` 的校验、原子落盘、换屏后按比例重算 |
| `app/main.js` | `walk:get` / `walk:set` IPC；框选期间的整窗可交互与 Esc 兜底（`pet:walkselect`）；游戏模式切断框选 |
| `app/preload.js` | `petHost.walk.{get,set,selecting,onSelectCancel}` |
| `web/index.html` | 设置区、框选遮罩、走动循环（rAF）、巡游决策、聊天拦截、`petAPI.walk` 调试口 |

## 关键设计（按验收口径）

- **范围**：`walk.json` 存 `{enabled, rect, win, displayId, speed}`。没框选 = 整个工作区。
  存了 `win`（框选时的窗口尺寸），读的时候若窗口尺寸变了就按比例搬，再与工作区求交 —— 换屏/改分辨率不会留下一个整块跑到窗口外的范围。
- **二维有界**：范围转成「角色左上角的闭区间」`petBox`。范围放得下整块画布才允许走（`fitsRect`）；
  放不下时**不走、不巡游**，设置面板与聊天回复都会说清楚「至少要多大的范围」，而框选值原样保留，方便用户对照着重框。
  每帧 `stepToward` 之后再 `clampPet`，所以**整块画布**（含脚下阴影）不会出框。
- **朝向**：`facingOf(dx)` 只看水平分量；往左演 `walk_left`、往右演 `walk_right`。
  两个素材只到一个时，用另一个 `scaleX(-1)` 镜像凑方向（`WALK.flip`，与菜单镜像叠加而不是互相覆盖），镜像后逐像素命中测试仍然对齐。
- **优先级**：`拖动 > 走动/巡游 > 固定片段 > chatBusy > 表情 > 媒体 > 看板 > 面板 > 长任务 > 一次性动作 > 空闲`。
  走动期间打开菜单/搜索/自检、进入游戏模式、开始框选、手动抓角色 → 走动**立即停**（`walkStart` 在暂停态直接拒绝，不会留下等不到的 Promise）。
- **巡游**：默认关闭；只在「巡游开着 + 空闲足够久 + 没有更高优先级状态」时随机取一个范围内的点走过去，到点歇 2.2~6 秒。
  「停下」指令会把它关掉（写盘），设置里可以再勾上。
  **设置/聊天面板打开时巡游让路**（自动停下，开关不自行关掉）；聊天指令这类显式动作照常执行。
  巡游自己走到点不算「用户操作」，不会把空闲计时推后 12 秒；巡游开着时空闲随机也不再抢动作。
- **走到一半范围变了**：每帧都按**当前**包围盒重算目标（`clampTarget`），范围变小/画布放大时目标被夹回来继续走完；
  位置 400ms 没动（被夹住）就当场收敛。所以走动 Promise 一定 resolve，不会出现「卡在边界原地走」。范围缩到装不下画布时立刻收尾并给出提示。
- **聊天指令**：只有 `sendChat()` 一处解析**用户这次输入**；命中就不发给任何后端（不需要 API key，也不写进 AI 上下文）。
  AI 回复文本、历史记录重放都不经过解析 —— 结构上只有 1 个解析点，e2e 有断言。
- **框选与点击穿透**：框选是第二个允许「整窗强制可交互」的场景（第一个是拖动）。退出路径有 4 条（拖完松开、Esc、窗口失焦、右键），
  全部都走 `walkSelEnd()` → `pet:walkselect false` → `setMouseInteractive(false, true)` 恢复穿透。
  Esc 会被页面 keydown 与主进程全局兜底各收到一次，用 350ms 短窗口保证「只退框选、不顺手关面板」。
- **游戏模式**：主进程在进游戏模式时切断框选并通知页面收遮罩；页面侧 `walkSelStart()` 也拒绝在游戏模式下开始框选。
  另外页面启动时会**主动读一次**主进程游戏模式（开着游戏启动桌宠时，事件不会再补发）。

## 验收怎么跑

```bash
cd electron-src

# ① 纯逻辑（34 项）：几何 / 指令解析 / 配置
PET_TEST_TMP=../tmp/tdir node --test tests/walk-geom.test.cjs tests/walk-command.test.cjs tests/walk-config.test.cjs

# ② 端到端（62 项）：真 Electron + 真页面 + 真 preload + 本机 http 视频
PET_TEST_TMP=../tmp/e2e-walk WALK_EVIDENCE=../证据/e2e-walk EXPECT_VER=0.7.0 node tests/e2e-walk.cjs

# ③ 包内自检（22 项，打完包后对 exe 也能跑）
"<electron.exe>" --user-data-dir=<隔离目录> <app 或 exe> --walktest --exit-after-test

# ④ 演示片段（真 exe + CDP 抽帧，画面里不含真实桌面）
node tests/demo-walk.cjs
```

- ②③ 的交互走 CDP `Input` 域（浏览器真实输入路径），不是页面内 `.click()`；也不是操作系统级鼠标。
- ②会依次启动 3 个隔离实例（主流程 / 重启保留 / 游戏模式），全部用 `--user-data-dir` 隔离，不碰用户真实配置。
- e2e 结果写 `证据/e2e-walk/run-*.json`，含每项明细与子进程 stdout（`WALKSEL true/false` 等日志行）。
